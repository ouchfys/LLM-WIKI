# PaperWiki 案例：Tool 与 MCP 的边界

## 用户需求

用户输入“RSIAgent 这篇论文入库”。系统需要发现候选、确认论文身份、提交解析入库、等待结果并确认 Wiki 产物。用户不需要知道论文编号或 MCP 的存在。

## 三层职责

| 层次 | 解决的问题 | 本项目中的对应实现 |
| --- | --- | --- |
| 模型工具接口 | 模型可以做什么、传哪些参数、如何理解返回值 | `arxiv(action=search/lookup/import/status)` |
| 业务实现 | 如何搜索论文、处理限流、缓存 PDF、提交入库 | `ArxivClient`、`ArxivService`、`WikiIngestionClient` |
| MCP 接入协议（可选） | 不同宿主如何发现和调用外部提供的能力 | 本项目独立 MCP 入口已经移除 |

Function Calling 让模型表达工具调用，宿主执行它。宿主既可以调用本进程函数，也可以通过 MCP 客户端调用服务。MCP 的 tools/list 和 tools/call 提供标准化发现与调用；一个 MCP 服务可以提供多个工具，并不自动变成“一个模型工具”。MCP 还可提供 resources、prompts 等能力。

参考：[MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)、[MCP 工具协议](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。

## 实际改动与原因

项目曾保留独立 arXiv MCP 服务，但网页聊天直接调用共享 Python 服务，并未走 MCP 客户端。关键词搜索存在于底层和 MCP 入口，却没有注册给聊天模型；聊天因此可能通过 Shell 重新构造搜索请求。

本次删除未接入聊天路径的 MCP 服务、依赖和启动配置，保留业务实现。将查询、入库、状态三个聊天工具合并为 `arxiv`，并加入已有的关键词搜索能力。模型工具总数由本次修改前的 9 个变为 7 个。

当前路径：

```text
用户请求
→ 模型生成 arxiv 的 action 和参数
→ PaperWiki 调用共享 Python 服务
→ arXiv 官方 API / PDF 下载
→ 需要入库时，调用现有 FastAPI 入库接口
→ 后台解析编译，状态查询，Wiki 读回
```

入库路径仍复用现有 HTTP 接口，不能描述成整个流程“零网络开销”。移除 MCP 不会让 arXiv 官方接口限流、论文重名或解析错误消失。

## 什么时候适合 MCP

- 同一论文服务要给多个支持 MCP 的智能体宿主使用，避免各写一套适配。
- 服务由其他团队维护，需要独立部署、发布和明确的客户端契约。
- 接入已有第三方 MCP 服务，比自行对接其业务接口更省工作。
- 产品需要动态发现和接入外部工具，并愿意承担连接、认证、版本和运行管理。

不同语言、独立进程或远程部署可提高采用 MCP 的价值，但它们本身并不意味着必须使用 MCP；普通 HTTP API 等方式也可能合适。

## 什么时候会增加工作量

只有一个内部调用方，业务代码已经在同一 Python 项目中，且没有外部复用需求时，再加 MCP 会引入服务入口、客户端适配、通信错误、取消与恢复的映射以及额外集成测试。收益取决于是否真的需要跨宿主互操作。

MCP 不自动决定搜什么、何时结束研究、如何识别重名论文，也不替代业务审批、任务幂等或数据权限控制。工具声明为只读也不能替代实现层的权限约束。

## 合并工具的收益与代价

一个 `arxiv` 入口使论文操作集中，减少顶层名称的重复。但四种动作仍有不同必需参数和副作用，所以增加了动作参数检查，并使调度和恢复识别 `action`。工具数量减少不等于 token、费用或延迟按比例下降；尚未以线上对照实验验证这些指标。

## 面试时的说法

> 我把工具接口、业务能力和接入协议分开了。论文搜索、下载和入库是业务能力，模型通过 arxiv 工具选择动作；MCP 是让其他宿主发现和调用这些能力的可选协议。项目当时只有内部 Python 调用方，MCP 服务并没有被网页聊天使用，所以我移除了这层入口，复用原有服务并补上按名称搜索。将来有多个客户端要复用时，可以在稳定业务接口之外重新增加 MCP 适配。这个选择依据调用边界和复用需求，合并后也验证了读写调度和中断恢复。

## 验证边界

回归测试应覆盖原生调用和 JSON 回退的一致性、名字搜索到已观察编号再入库、缺参数不执行、只读并发与写入串行、任务失败与状态读取成功的区别、历史调用恢复兼容。只读线上搜索可验证接口连通和候选结果；不应把它报告为整篇论文成功入库。

2026-09-28 通过当前统一工具实际执行 `arxiv(action="search", query="RSIAgent", limit=5)`，返回一个候选：`2609.15364v2`，标题为 “RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments”。本次没有提交该论文入库，搜索排名和结果数量也不保证在未来保持不变。
