# PaperWiki：知识库、记忆与会话上下文

## 职责边界

- `system/wiki/`：论文和主题知识库。Markdown 是知识正文；检索结果作为证据进入请求。它不是用户记忆。
- `system/memory/user_memory.py`：稳定用户偏好、带有效期的讨论话题。与现有学习画像一起工作。
- `system/conversation/`：原始消息、工具观察记录、压缩检查点和本轮上下文预算。
- 三者共享现有 SQLite 基础设施，但写入入口和删除语义分开。旧 `system.memory.session_store/context_*` 保留导入兼容层；没有迁移或重写用户的 Wiki 文件。

## 模型容量与运行预算

DeepSeek V4 Flash/Pro 默认按官方 1M 上下文配置，代码以 1,000,000 Token 作为保守数值。未知模型要求显式配置 `PAPERWIKI_CONTEXT_WINDOW`，不会假定它也支持 1M。官方规格：https://api-docs.deepseek.com/quick_start/pricing/

可选 `PAPERWIKI_CONTEXT_RUNTIME_LIMIT` 是用户为了成本、延迟设置的应用上限，与模型容量区分。默认不额外限制。窗口不得超过已知模型上限。

默认预留输出 4096、安全余量 2048，输入上限 993856；约在有效窗口的 80% 触发整理，原样保留最新约 16% 历史。保留量还会根据本轮非历史内容占用缩小，但至少保留最新完整问答组。这些比例是可调策略，不是模型规格。

不再读取 `PAPERWIKI_CONTEXT_HISTORY/PLANNING_HISTORY` 两个旧分区开关。工具规划和回答使用同一个可更新的历史列表，历史可使用剩余输入空间；不另设 4K/8K 截断。未触发压缩时，预算允许就携带全部有效历史。Wiki 正文、网页、画像仍有各自的局部检索和展示上限，知识库不会整体灌入模型。

`ContextPolicy.from_env()` 解析实际模型及环境配置。修改配置后重新启动 `paperwiki web`。手动 `/compact` 使用聊天模型，论文入库的摘要模型保持独立。

## 每次模型请求的路径

1. 读取最近检查点之后的全部有效历史，加已有摘要；与当前问题组成会话快照。
2. 加入阶段指令、稳定画像、本轮工具观察和所需知识库资料；原生工具调用还计入完整工具定义。
3. 测量完整候选请求。未达阈值时不自动总结历史。
4. 达到压力阈值，先缩减工具观察的派生文本：优先保留最新完整观察块，超大单块明确标记省略。原始工具观察仍存在 SQLite，可分页读取。
5. 重新测量，仍有压力才用聊天模型总结早期完整问答组。
6. 原子保存检查点并更新共享历史列表，当前请求重新组装。规划后、工具循环中和最终回答构建时均适用。
7. 发送前再次检查整个请求与输出预留；当前问题超长时明确报错，不静默裁剪。

本轮已经执行的工具状态由 RunControl 保留，压缩历史不重跑工具。已打开 Wiki 页沿用已有的 ID 去重合并逻辑。

## 可追溯压缩

摘要提示词要求保留：目标、明确约束、已确认及已否定方案、证据引用、未解决问题和下一步；重要决定保留来源消息 ID。摘要是有损工作记录，不是知识库事实。

`context_checkpoints` 保存每次成功摘要、上一次覆盖边界、新覆盖消息 ID、时间和统计；`sessions.settings_json` 中的旧字段仍作为当前检查点的兼容投影。

摘要与边界在同一 SQLite 事务中提交，通过旧摘要和旧边界比较并交换，避免并发旧结果覆盖新结果；边界必须属于该会话。模型失败、取消或会话被删除时不写入半成品。启动时增量建表，不改写旧历史。

自动压缩单次最多处理一个有界前缀、最多四次摘要调用。极长积压可能需要在后续请求继续处理。手动 `/compact` 分批覆盖完整选定记录；离线选项仅为带标识的有损摘录。

## 历史找回与工具记录

Agent 增加三个只读工具，原生 Function Calling 与 JSON 回退路径均可使用：

- `search_session_history(query, limit)`：按文字片段搜索当前会话原始消息，包括已压缩消息；返回 ID、命中附近摘录。
- `read_session_messages(start_id, end_id, offset)`：按 ID 范围读取原文；长消息按字符偏移分页。
- `read_tool_result(result_id, offset)`：读取保存的工具观察结果，返回下一页位置。

会话身份来自服务端当前 RunControl，模型不能通过参数指定其他会话。历史搜索采用 SQLite 字面子串匹配（支持中文），不是语义检索。工具观察表保存执行器返回的完整观察；上游检索器已经限制的网页/论文片段，不会因此变成完整外部源文件。论文原件仍由知识库来源系统管理。

## 跨会话记忆

稳定偏好只在出现“以后、默认、始终”等明确持续要求时提取；“这次详细讲讲”不自动固化为长期回答风格。含否定的复杂要求保守跳过，不从关键词猜测反向偏好。现有偏好管理接口仍可直接编辑。

偏好按 key 更新，保存用户原文依据、来源会话、时间和 user 作用域。同一偏好新值替换旧值。讨论话题继续使用现有 30 天有效期；学习画像的目标/兴趣信号仍是启发式推断，不等同于用户确认的项目决定。

普通聊天、自动压缩不写 Wiki。`/wiki` 是用户明确要求沉淀知识的独立流程，仍区分论文事实、AI 综合和用户洞见。

## 删除和界面

整理上下文不删除原始记录。清空/删除会话会一并删除消息、检查点和工具观察；用户长期记忆独立保留，其中可能包含来自已删除会话的偏好依据。Wiki 文件与知识索引不在会话删除路径中。

聊天回答下方显示可展开的上下文用量：最后一次模型请求的估算输入、窗口、是否发生压缩，并解释知识库独立保存。内部 ID 和编译器信息不进入知识阅读正文。

## 计量与实际边界

默认使用 cl100k_base × 1.25 估算，明确标记 `cl100k_estimate_1.25x`；这是参考分词器，不是 DeepSeek 精确 tokenizer，25% 也不是数学保证。可配置匹配模型的本地 tokenizer.json；不可用时回退 UTF-8 字节估算。模型接口的真实 usage 继续保存在原有运行 trace；尚未实现自动校准估算器。

会话历史仍经现有问答文本适配器进入提示词；没有照搬 Pi 的树状分支或 DSH 的完整事件回放协议。若摘要失败或当前不可分单元过大，最终硬预算可能省略旧历史，工具仍可找回原文。当前没有实现所有提供方溢出错误的自动分类与重试。

长期任务决定的自动抽取、语义历史检索、摘要事实保真评测均不是本次宣称完成的能力。更长窗口不会自动保证更好的回答，需要用真实任务验证。
